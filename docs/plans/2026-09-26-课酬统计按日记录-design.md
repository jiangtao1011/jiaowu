# 课酬统计「按日记录」方案设计

日期：2026-09-26

## 一、背景与问题

现有课酬统计以 `schedules`（每周固定重复规则表）为根基：每条只有「星期 + 节次」，统计「按时间段」时用 `weekdayCount` 数出区间内某星期几出现几次再乘系数。这导致三处结构性问题：

1. **临时变动无「单日」语义**。调课/代课/停课用 `effective_from`/`effective_to`，只能表达「从某天起永久生效」，表达不了「就这周三换一下」「这周五全校停课」等单次/短期变动。
2. **答疑被误当成每周重复**。答疑审核通过后直接 `INSERT` 进 `schedules`（`period_type='答疑'`），变成「每周固定都答疑」，而答疑本质是「实际发生一次计一次」。
3. **统计靠推算而非事实**。真实课酬应按「这学期到底上了几节课」结算，而非按课表拍脑袋推。

## 二、核心决策（已与用户确认）

1. **以「按日上课记录」为根基**：新增 `lesson_instances` 表，每条记录带具体日期。固定课由课表展开到日期；临时变动/加课/答疑落成一条日期记录。统计按日期范围精确汇总，可逐节追溯。
2. **答疑「两者结合」**：有固定排班的答疑走课表展开计酬；临时/不定期答疑由教师按次填报（带日期+节数），审核通过后计酬。
3. **引入「上课日/调休」校历**：维护学期上课日历（上课/放假/补课+补哪天），固定课自动展开到正确日期；「某天全校停课」「周六补周一」只需改校历一处，不再逐节手工调。

## 三、数据模型

### 3.1 新表 `school_calendar`（学期上课日历）

| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| date | TEXT | 具体日期 `YYYY-MM-DD`，唯一 |
| type | TEXT | `上课` / `放假` / `补课` |
| make_up_for | TEXT | 仅 type=补课 时有值：补哪一天的课，格式 `YYYY-MM-DD` 或周几 |
| note | TEXT | 备注（如「中秋放假」「周六补周一」） |
| created_at | TEXT | |

- 展开固定课时：课表某「周一」的课，只落在 `date 是周一且 type=上课` 的日期；若存在 `type=补课 且 make_up_for 指向周一` 的日期，也落在该日期。
- 「某天全校停课」= 把该日期标为 `放假` 即可，整表联动。

### 3.2 新表 `lesson_instances`（按日上课记录）

| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| schedule_id | INTEGER NULL | 来源课表条目（展开生成时回填）；手工加课/临时答疑为 NULL |
| class_id | INTEGER | 上课班级（走班填走班班 id） |
| teacher_id | INTEGER | 任课教师（代课时已指向实际授课人） |
| subject | TEXT | 学科 |
| date | TEXT | 实际上课日期 `YYYY-MM-DD` |
| period_no | INTEGER | 节次 |
| period_type | TEXT | 正课/早自习/晚自习/答疑 |
| term | TEXT | 常规/夏令营/冬令营/… |
| source | TEXT | `schedule`（课表展开）/ `adjust`（代课/调课）/ `extra`（加课）/ `qna`（答疑填报） |
| parent_id | INTEGER NULL | 该记录由哪条记录派生（代课/调课时指向原记录），便于追溯 |
| note | TEXT | 备注 |
| created_at | TEXT | |

- 唯一性：`(schedule_id, date, period_no, teacher_id, class_id)` 或对无 schedule 的记录用 `(source, date, period_no, class_id, teacher_id)`，避免重复展开。
- 统计直接 `WHERE date BETWEEN ? AND ?`，逐条折算汇总，不再推算星期几。

### 3.3 `qna_lessons` 增加列

| 列 | 说明 |
|---|---|
| date | TEXT，答疑发生日期（临时填报时必填） |
| period_count | INTEGER，节数（默认 1） |

固定排班答疑不走此表计酬，仍由课表 `period_type='答疑'` 展开到 `lesson_instances`。

### 3.4 `lesson_instances` 增加 `source_id` 回链

| 列 | 说明 |
|---|---|
| source_id | INTEGER NULL，回链来源业务记录（如 `qna_lessons.id`），供撤回/删除答疑时定位并删除已生成的上课记录 |

审核通过生成答疑上课记录时写入 `source_id = qna_lessons.id`；撤回/删除答疑时按 `source='qna' AND source_id=?` 联动删除。

### 3.5 答疑生命周期（含修改）

答疑状态机：`pending` →（审核）`approved` / `rejected`；`approved` →（撤回）`withdrawn`。

- **填报人**：可编辑/删除自己「待审核」的记录。
- **管理员**（教务处/教务员/admin）：可编辑/删除任意状态记录；可审核；可撤回「已通过」记录。
- **编辑**（`PATCH /:id`）仅改记录本身，不改状态。
- **删除**（`DELETE /:id`）联动删除该答疑已生成的上课记录（`source=qna`）。
- **撤回**（`PATCH /:id/withdraw`）把 approved 置为 withdrawn，并联动删除已生成的上课记录。

## 四、展开与生成机制

### 4.1 生成 `lesson_instances`（幂等）

后端提供 `POST /api/stats/generate`，参数 `{ from_date, to_date }`：

1. 读 `school_calendar`，构造「某日期 → 对应星期几」映射（补课日按 `make_up_for` 覆盖）。
2. 读当前有效课表（`schedules` 中 `effective_to IS NULL`），对每条按 `day_of_week` 匹配出落在区间内的日期列表。
3. 对每个 (课表条目, 日期) 组合，若 `lesson_instances` 已存在则跳过，否则插入一条 `source='schedule'`。
4. 幂等：重复调用不会重复生成（靠唯一性判断）。

### 4.2 单日变动

`POST /api/stats/instance/adjust`：对某条已生成的 `lesson_instances` 做代课/调课/停课：

- **代课**：把该条记录标 `source='adjust'`、`parent_id=原记录id`，`teacher_id` 换成目标教师（或插入新记录、原记录标记停课）。
- **停课**：删除该条记录，或插入 `source='adjust'` 的「取消」标记。
- **加课**：直接 `POST /api/stats/instances` 插入 `source='extra'` 的记录。

### 4.3 整体临时变动

不逐节调，改 `school_calendar`：把某天标 `放假`（全校/年级停课）、某天标 `补课`（补某天），重新生成即可联动。年级级停课后续可扩展 `grade` 字段，本次先做全校级。

## 五、统计口径

`GET /api/stats/summary?from_date=&to_date=&term=&teacher_id=`：

- 直接汇总 `lesson_instances` 中 `date BETWEEN from AND to` 的记录。
- **折算规则沿用现有**（不重复发明）：
  - 正课（常规）= 节数 × 学科系数 × 班额系数
  - 早自习 = 节数 × 早自习系数
  - 晚自习/答疑 = 固定课酬（节数 × 单价）
  - 非规时段 = 节数，课酬 = 节数 × 教师课酬标准
- 输出：`total`（原始节数）、`weighted_total`（折算课时）、`pay_total`（课酬）、按 `period_type`/`term` 分布。

保留旧 `GET /schedules/summary` 向后兼容（仍基于 `schedules` 推算），但前端统计页默认切换到新的按日统计。

## 六、API 清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/stats/calendar | 列出校历（可按日期范围） |
| PUT | /api/stats/calendar | 批量设置/更新校历（含补课映射） |
| POST | /api/stats/generate | 从课表按日期范围展开生成上课记录（幂等） |
| GET | /api/stats/instances | 列出上课记录（按日期/班级/教师筛选） |
| POST | /api/stats/instances | 手工加课（source=extra） |
| POST | /api/stats/instance/:id/adjust | 单日代课/停课 |
| DELETE | /api/stats/instance/:id | 删除某条上课记录（撤销） |
| GET | /api/stats/summary | 按日统计汇总（新口径） |

## 九、风险与兼容

- 旧数据：`lesson_instances` 首先生成需要一次「展开」，现有 `schedules` 数据无需迁移。
- 旧 `/schedules/summary` 保留，不影响其他依赖方。
- 走班/分层/班额折算逻辑全部复用 `loadContext()`，不重复实现。
