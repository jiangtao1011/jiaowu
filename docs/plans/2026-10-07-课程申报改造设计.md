# 课程申报改造：自定义表单 + 分享填报 + 审核计酬

日期：2026-10-07
状态：头脑风暴定稿，待实施

## 1. 背景与目标

现有「课程申报」（Tab 2）是一个轻量的开课审批留档：教务员建「申报任务」→ 教师填固定字段（course_name/schedule_time/duration 等）→ 教务员审核改状态。**审核通过后不产生任何课时/课酬记录**，与统计中心脱钩。

本次改造为完整的「课程申报 → 教师填报 → 审核 → 计酬」闭环：

1. **申报内容由教务员定制**：设置课程时自定义「教师需上报哪些字段」（字段类型可选文本/日期/数字/下拉/多行文本）。
2. **分享二维码/链接填报**：生成分享二维码或链接，教师手机扫码/点开填写（需登录，自动识别「我是谁」）。
3. **审核通过挂钩计酬**：复用现有课酬链路——有的课按标准算钱（单价 × 节数），有的按课时折算（节数 × 系数）。审核通过生成 `lesson_instances`，进入统计中心与课酬报表。

## 2. 头脑风暴结论（已确认）

1. **自定义字段**：每课（任务）自定义字段集合，字段类型可选文本/日期/数字/下拉/多行文本。
2. **计酬方式按课程固定一种**：课程创建时确定「按标准算钱」或「按课时折算」，一个课程一种。
3. **必有课时数字段**：计酬需一个「课时数/节数」数字，审核通过后才能算钱/折算。
4. **身份识别需登录**：教师扫码/点链接后需登录，复用现有账号↔教师档案绑定，计酬准确落到人头。
5. **计酬复用现有链路**：审核通过生成 `lesson_instances`，走现有统计中心与课酬报表（与早自习/答疑同一条链路）。
6. **折算为简单系数/单价**：「折算」= 节数 × 系数（类似早自习）；「算钱」= 单价 × 节数（类似按次计酬）。不引入正课的「学科系数 + 班额系数」。

## 3. 数据模型变更

复用现有 `application_tasks`（课程/任务）+ `applications`（填报记录）两张表，扩展字段；计酬复用 `lesson_instances`。

### `application_tasks` 扩展

| 新增列 | 说明 |
| --- | --- |
| `form_schema` | JSON，自定义字段定义数组 `[{key,label,type,required,options}]`，type∈文本/日期/数字/下拉/多行文本 |
| `pay_mode` | 计酬方式：`按次计酬`（单价×节数）或 `折算`（节数×系数） |
| `pay_rate` | 数值：按次计酬时=单价（元/节），折算时=系数 |
| `period_type` | 计酬类型名，写入 lesson_instances.period_type（按次计酬时对应 period_type_pays 字典名或自定义；折算时对应「早自习」这类折算型） |
| `subject` | 学科（计酬展示/折算用，可选） |
| `share_token` | 分享 token，生成分享链接/二维码用 |

保留现有 `title/type/course_type/time_desc/duration/content_desc/deadline/filler_role` 字段，其中部分可并入 form_schema（但保留 `title`、`deadline`、`filler_role` 作为课程元信息）。

### `applications` 扩展

| 新增列 | 说明 |
| --- | --- |
| `form_data` | JSON，教师填报的字段值（按 form_schema 的 key 存） |
| `period_count` | 课时数/节数（必填，计酬依据） |

保留现有 `course_name/course_content/schedule_time/duration/remark` 作兼容，但新版填报主要写入 `form_data`。

### 计酬落地（复用）

审核通过后，按 `application_tasks` 的计酬配置 + `applications` 的 period_count，生成 `lesson_instances` 记录（`source='course'`），`period_type` 由课程配置决定：

- 按次计酬：`period_type` = 课程配置的字典类型名（或自定义，需在 `period_type_pays` 里有对应单价）→ `computePay` 走「单价 × 节数」。
- 折算：`period_type` = 「早自习」或其它折算型 → `computePay` 走「节数 × 系数」。若折算系数不是全局 0.5，需要让 `computePay` 支持按记录读系数（见第 6 节风险点）。

## 4. 折算类型字典（核心架构变更）

当前 `computePay` 对折算只认写死的 `period_type === '早自习'`，系数取全局 `period_settings.early_coefficient`（0.5）。为支持「不同课程不同折算系数」，将**折算泛化为一个字典**，与「按次计酬字典 `period_type_pays`」对称：

- 新表 `period_type_coefficients`（`name UNIQUE` + `coefficient`），seed 一条 `早自习=0.5`。
- `computePay` 的分支改为：命中 `periodTypeCoefficients` → 折算课时 = 节数 × 系数、pay=0（替代原「早自习」硬编码分支）。
- `loadContext` 加载该字典。
- `period_settings.early_coefficient` 迁移进字典（或保留只读兼容）；统计配置 UI 改为维护「折算类型字典」。
- **stats.js 聚合泛化**：`early_count/early_weighted` 单列、`types` 列、导出表头里的「早自习」全部改为按 `periodTypeCoefficients` 动态遍历，避免新增折算档位后统计缺列。

**计酬映射（定稿）**：
- **按标准算钱**（单价×节数）：课程选一个 `period_type_pays` 字典类型（晚自习/答疑/晚练/自定义），审核通过生成 lesson_instances 时 `period_type` 用该类型名 → `computePay` 走「单价×节数」。
- **按课时折算**（节数×系数）：课程选一个 `period_type_coefficients` 折算档位（默认早自习 0.5，可新增），`period_type` 用该档位名 → `computePay` 走「节数×系数」、不计钱。

## 5. 流程与 API 设计

### 教务员端（桌面 `Applications.jsx` Tab 2）

- **创建课程**：填标题、截止时间、填报人角色；定义自定义字段（增删字段，每个字段设 key/标签/类型/是否必填/下拉选项）；选计酬方式（按次计酬选类型→带出单价，或折算→填系数）；选学科（可选）。
- **生成分享**：创建后生成 `share_token` + 分享链接 + 二维码（复用 Notices.jsx 的 `qrcode` 实现与 `publicBase`）。
- **审核**：查看某课程下的填报记录，通过/驳回；通过后生成计酬记录。

### 教师端（手机，新增分享填报页）

- 路由 `/course/:token`，需登录（复用 AuthGuard）。
- 打开后展示课程标题 + 自定义表单（按 form_schema 动态渲染）+ 课时数字段。
- 提交写 `applications`（`form_data` + `period_count`，状态 pending）。

### API（`routes/applications.js` 扩展）

- `POST /tasks` — 创建课程（含 form_schema/pay_mode/pay_rate/period_type/subject），返回含 `share_token`/`share_url`。
- `GET /tasks` — 课程列表（含填报人数）。
- `GET /tasks/:taskId` — 课程详情（含 form_schema，教师填报页用）。
- `GET /course/:token` — 公开（需登录）课程详情，供分享页。
- `POST /tasks/:taskId/apply` — 教师填报（form_data + period_count）。
- `GET /tasks/:taskId/applications` — 某课程填报记录。
- `PATCH /applications/:id/review` — 审核；通过时生成 lesson_instances（source='course'）。
- 撤回/删除联动删除已生成的上课记录（复用 qna 的模式，source='course'）。

## 6. 风险点与待确认

1. **折算字典迁移**：`period_type === '早自习'` 的硬编码散落在 `computePay`、`stats.js` 的聚合/导出/勾稽校验多处，需一并泛化为字典遍历。这是本次改动量最大、最需回归测试的部分。早自习作为字典默认项保持向后兼容。
2. **period_type 与字典的约束**：按次计酬的课程必须选一个已存在的 `period_type_pays` 类型，折算课程必须选一个 `period_type_coefficients` 档位，否则 `computePay` 会当正课算（金额 0）。创建课程时要校验。
3. **分享链接的公开性与登录**：教师端需登录，但链接本身带 token，任何人拿到 token 点开仍要登录才能填，token 只用于定位课程、不泄露教师身份。
4. **删除/撤回联动**：审核通过后删除/撤回，需联动删除 `source='course'` 的 lesson_instances，避免残留计酬。
5. **兼容**：现有 `applications` 记录（徐卫华那条已删，表已空）与 `application_tasks`（任务 1 保留）需兼容新字段（`ensureColumn` 迁移）。
