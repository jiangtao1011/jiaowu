# 课表版本控制与补课/放假方案设计

日期：2026-09-27（已实施并通过端到端验证）

## 一、背景与目标

现有课表体系存在三个未覆盖的业务场景：

1. **全校放假、各年级时间不同、放假期间不计酬**——需按年级精确控制放假区间。
2. **放假期间使用补课课表（≠正式课表）或补某一天的课**——补课期间课酬按「节假补课」标准。
3. **课表整体/部分更换，从某时间节点按新表重新统计**——需给课表加「版本/生效区间」语义。

核心判断：**无需新增数据表**。现有 `schedules.term`（含「节假补课」档）、教师 `pay_standard['节假补课']` 单价、`schedules.effective_from/effective_to`、`school_calendar`（已支持 date+grade）已能承载全部场景。

## 二、核心决策（已与用户确认）

1. **换课表语义 = 带生效日期整体替换**：导入时指定「从哪天起生效」，选定范围内旧课表整体关闭、新表启用；历史记录保留，`as_of` 快照仍能查旧表。
2. **替换范围（scope）可选**：全校 / 年级 / 时段，支持「换一部分」；另有 `append` 追加模式（默认）。
3. **补课课表按年级一套**：复用 `schedules` 表，`term='节假补课'` 的课表即补课课表，挂载在班级（class 天然带 grade），按年级自然相交。
4. **补课课表 = 独立的一套每周课表**：自带 `effective_from/effective_to` 生效区间，在区间内按**当天实际星期几**上课，并**整体取代**该年级正式课表（已确认整体取代，非按节覆盖）。
5. **补某天的课**（区别于补课课表）：由校历 `make_up_for` 映射，展开正式课表被补那天的课、`term` 覆盖为节假补课。
6. **校历类型**：`上课` / `放假` / `停课` / `补课`。放假与停课都让当天不排课不计酬，仅语义标签不同。

## 三、数据模型（复用现有，不建新表）

### 3.1 `schedules.term` 作为「课表身份」

- `常规` / 夏令营 / 冬令营 / 全员夏令营 / 全员冬令营 = 正式课表
- `节假补课` = 补课课表（独立生效区间，`effective_from/effective_to`）

补课课表「按年级一套」无需新列：每条记录挂在 `class_id`，`classes.grade` 天然提供年级维度。

### 3.2 导入接口参数

`POST /schedules/import`：

| 参数 | 说明 |
|---|---|
| `effective_from` | 新记录生效日（可空） |
| `effective_to` | 新记录结束日（可空，左闭右开） |
| `scope` | `append`（默认，追加）/ `all`（全校替换）/ `grade`（年级替换，带 `grade`）/ `term`（时段替换，带 `scope_term`） |
| `grade` | scope=grade 时的年级 |
| `scope_term` | scope=term 时的时段 |

## 四、场景 3 · 换课表：导入带生效日期整体替换

`scope=all/grade/term` 且带 `effective_from` 时执行「关闭旧表 + 写入新表」：

1. 关闭旧表：`UPDATE schedules SET effective_to = :effective_from WHERE effective_to IS NULL AND <scope 过滤>`。
   - all：无额外条件；grade：`class_id IN (SELECT id FROM classes WHERE grade = :grade)`；term：`term = :term`。
2. 写入新表：`INSERT`，`effective_from/effective_to` 按参数。

`scope=append` 只新增、不关闭旧表（补课课表即用此模式 + 区间）。旧记录**物理保留**（仅 `effective_to` 被设置），`as_of` 快照仍能查旧表，变化前统计不受影响。

## 五、场景 1 · 放假 / 场景 · 停课

`school_calendar` 支持 `(date, grade)` 唯一 + `type` 含放假/停课。`generate` 对放假与停课都跳过、不计酬。按年级各标一条即实现「各年级放假时间不同」。前端校历卡片支持「起始日~结束日 + 年级 + 类型」区间批量标记。

## 六、场景 2 · 补课：`generate` 三态展开

`generate`（stats.js）对区间内每一天、每个年级：

1. **放假/停课**：跳过。
2. **补课课表**（`term=节假补课`）：在自身生效区间内、非放假/停课日，按当天实际星期几展开，`term='节假补课'`。当天该年级有活跃补课课表时，正式课表**整体让位**。
3. **正式课表**（`term≠节假补课`）：当天该年级无活跃补课课表时展开。校历「补课」日（补某天）用正式课表被补那天的课并标 `term='节假补课'`。

关键点：补课期间生成的 `lesson_instances` 一律 `term='节假补课'`。`computePay` 对非规时段已按 `pay_standard['节假补课']` 计酬，课酬无需改代码。

## 七、重新生成

`generate` 支持 `replace=true`：先删除区间内 `source='schedule'` 的记录再重新展开，避免改表/改校历后叠加重复计酬。前端默认开启。

## 八、API 清单（最终实现）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/schedules/import | 加 `effective_from`/`effective_to`/`scope`/`grade`/`scope_term`；替换模式先关旧表再写新表 |
| PUT | /api/stats/calendar | 支持按日期区间批量展开（`date` 或 `from`~`to`，含停课类型） |
| POST | /api/stats/generate | 三态展开 + `replace`（先删后建） |

## 九、验证结果（真实数据端到端，已还原）

- 放假/停课/休息日不生成记录，不计酬。
- 补课课表在生效区间内按当天星期几展开，正式课表整体让位，课酬按节假补课标准。
- 换课表后生效日前按旧表、生效日后按新表，历史快照正确。
- 重复生成不叠加（先删后建）。

## 十、风险与兼容

- **兼容旧导入用法**：`scope=append` 默认，行为与旧版一致。
- **旧 `lesson_instances` 不受影响**：仅显式「重新生成」删除区间内 source=schedule 记录。
- **课酬计算零改动**：复用 `computePay`，节假补课档已存在。
- **补课课表整体取代**：已确认；若未来要「按节覆盖」，需改 `generate` 的让位判定。
