# 早自习自主申报设计

日期：2026-10-07
状态：头脑风暴定稿，待实施

## 1. 背景与目标

现有「课务申报」（`qna_lessons` + 审核状态机）以**按次计酬**为主：类型来自 `period_type_pays` 字典（晚自习/答疑/晚练等），计酬规则为「单价 × 节数」。

早自习此前只能靠**课表导入**进入系统（`schedules.period_type='早自习'`），没有自主申报入口。计酬核心 `computePay` 早已有早自习分支——折算课时 = 节数 × 早自习系数（`period_settings.early_coefficient`，默认 0.5），**不计钱**；统计中心也已单列「早自习节数/早自习折算课时」。

本次新增：**老师在手机上自主申报早自习**（桌面端同步补上填报/筛选/导入入口），复用现有审核与计酬链路。

## 2. 头脑风暴结论（已确认）

1. **申报对象 = 年级级**（年级统一，不落到具体班）。原因：一个老师会同时上几个班的早自习，早自习是老师包一个年级，`period_count` 即「课时数/次数」。
2. **走审核流程**，与答疑/晚自习一致（`pending → approved/rejected/withdrawn`）。
3. **系数保持全局单一** `early_coefficient`（默认 0.5），不按年级/学科细分。
4. **手机端保留节数步进器**（默认 1），兼容某些年级早读分多段的情况。

核心定性：**早自习是「答疑的孪生」**——同样走年级虚班 + 现有审核链路，唯一区别是计酬规则（答疑=单价×节数，早自习=节数×系数折算）。

## 3. 关键技术：复用年级虚班

早自习挂**年级虚班**（`classes` 里 `type='走班'` 的年级虚拟班，`class_members` 挂该年级行政班），机制与答疑完全一致（见 `2026-10-03-教师自主申报答疑晚自习设计.md` 第 4 节）：

- `qna_lessons.class_id` 指向年级虚班 id，满足 `lesson_instances.class_id NOT NULL` 约束，统计/导出 `JOIN classes` 不丢记录。
- 审核通过生成 `lesson_instances`，`period_type='早自习'`，`computePay` 逐条按「1 节 × 早自习系数」折算后累加，等于「课时数 × 系数」。
- 年级来源：老师可选年级复用 `GET /applications/self` 的 `qna_grades`（代课年级优先，否则全校年级）。

## 4. 后端改动（最小，集中在 `routes/applications.js`）

计酬核心 `context.js` 与统计中心**零改动**（早自习分支与汇总列早已就位）。

| 位置 | 改动 |
| --- | --- |
| `validPeriodType`（applications.js:17） | 放行 `早自习`：当前凡不在 `period_type_pays` 字典里的类型都回退「答疑」，必须让 `早自习` 作为合法类型通过，否则申报会变成答疑。**最关键** |
| `findDuplicate`（applications.js:30） | 早自习并入「年级级」判定分支（同教师 + 同类型 + 同日期 + 同年级），与 `答疑` 并列；否则会落进 else 的「年级+班级」口径，`class_id` 留空导致防重失效 |
| `POST /` 填报 | 桌面端早自习提交时**强制补上年级虚班 class_id**（见第 5 节），否则 `class_id=null`，审核通过时被 `if (q.teacher_id && q.class_id)` 拦住、不生成计酬记录 |

审核生成（applications.js:358）、删除/撤回联动（`DELETE /:id`、`PATCH /:id/withdraw` 按 `source='qna' AND source_id=?` 联动删除）**均免费复用，无需改动**。

## 5. 前端改动

### 手机端 `client/src/pages/MobileApply.jsx`

- 首页「申报答疑 / 申报晚自习」两个大卡片后，加第三个入口「申报早自习」（图标「早」字）。
- 表单与答疑一致：选年级（复用 `self.qna_grades`）+ 日期（默认今天）+ 节数（步进器默认 1，保留）+ 内容说明（选填）。
- `submit`：`period_type='早自习'`，`class_id` 取所选年级的 `virtual_class_id`。

### 桌面端 `client/src/pages/Applications.jsx`

- 填报表单「类型」下拉：现在只列 `typePays`（按次计酬字典），额外加固定项「早自习」（标注「折算型·不计钱」），提交 `period_type='早自习'`。
- **class_id 补全**：桌面端表单无「年级虚班」概念，早自习提交时根据所选 `grade` 反查年级虚班 id 自动带入（后端 `POST /` 也应兜底补全，双保险）。
- 列表筛选「全部类型」下拉加「早自习」项。
- 类型标签配色：补 `period-早自习` 的 CSS 类（`index.css`，现有 `period-答疑/晚自习/晚练` 已有配色）。
- 批量导入模板（`GET /applications/template`）：类型列说明加「早自习（折算型）」，示例行补一行早自习。

## 6. 验证重点

1. 申报一条早自习 → 审核通过 → 统计中心按日汇总，该老师「早自习节数 / 早自习折算课时」增加、金额不变（`pay=0`）。
2. 删除/撤回后折算回落。
3. 防重复：同教师 + 早自习 + 同日期 + 同年级，重复申报被拦；不同年级/不同日期不拦。
4. `validPeriodType` 放行验证：早自习申报在数据库中 `period_type='早自习'`，而非被回退成「答疑」。
