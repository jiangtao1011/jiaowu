# 课程申报重规划设计

日期：2026-11-09
状态：头脑风暴定稿，待确认后实施

## 一、背景与目标

现有「课程申报」是一套自定义表单 + 分享填报 + 审核计酬的闭环，但计酬方式只支持两种：「按次计酬（单价×节数）」和「折算（节数×固定系数）」。本次重规划要解决三类课的申报计酬，并统一到「课程申报任务」链路。

三类课（场景化定稿）：

1. **心理课（非周期课）**：老师填 时间、班级、节次 → 正课折算（学科+班额系数），每次固定 1 课时。
2. **一对一辅导**：老师填 辅导时间、时长、学生姓名、上传辅导资料 → 按次计酬（单价×节数），节数 = ⌈时长/90分钟⌉。
3. **竞赛课**：老师填 辅导时间、学生姓名、上课内容 → 固定折算（固定系数），课时数由老师自填。

## 二、头脑风暴结论（已确认）

| 问题 | 结论 |
| --- | --- |
| 申报链路 | 三类课统一走「课程申报任务」，分享二维码由老师自主填写 |
| 非周期课折算口径 | 同正课：节数 ×（学科系数 + 班额系数），只记课时不计钱 |
| 私人定制课 | 一对一按次计酬，单价 400 元/次；时长换算节数（1节=90分钟，向上取整） |
| 竞赛课 | 固定折算（竞赛系数 2.0），课时数老师自填 |
| 心理课计酬量 | 每次固定 1 课时，节次仅记录不参与量 |

## 三、场景化字段定义（form_data 承载）

| 场景 | 填报字段 | 计酬量计算 | 计酬方式 |
| --- | --- | --- | --- |
| 心理课 | 时间、班级、节次 | 固定 1 课时 | 正课折算 |
| 一对一 | 时间、时长(分钟)、学生姓名、辅导资料(附件) | ⌈时长/90⌉ 节 | 按次计酬 |
| 竞赛课 | 时间、学生姓名、上课内容 | 自填课时数 | 固定折算 |
| 非周期课折算口径 | 同正课：节数 ×（学科系数 + 班额系数），只记课时不计钱 |
| 其它类型 | 现有固定系数折算课（竞赛/培优/早自习等） |
| 私人定制课现状 | 已实现（字典一对一/一对二/一对多 + 手机自主申报），本次**迁入课程申报任务** |
| 非周期课挂班粒度 | 按班级申报（班额=该班人数） |

## 三、现有数据盘点

**计酬字典（已就位，无需新增表）**：

- `period_type_pays`（按次计酬）：晚自习 180 / 答疑 150 / 晚练 20 / 晚晚练 30 / **一对一 400 / 一对二 450 / 一对多 500**
- `period_type_coefficients`（固定系数折算）：早自习 0.5 / 竞赛 2.0 / 培优 1.5
- `subject_coefficients`（学科系数）、`size_bands`（班额系数）——正课折算复用

**课程申报表**：`application_tasks`（课程/任务）+ `applications`（填报记录），已有 `form_schema`/`pay_mode`/`pay_rate`/`period_type`/`subject`/`grade`/`share_token` 等列。

**计酬引擎** `computePay(ctx, r)` 现分支（[context.js](server/src/context.js)）：
1. `periodTypeCoefs.has(period_type)` → 折算 = 节数×固定系数，pay=0
2. `periodTypePays.has(period_type)` → 课酬 = 单价×节数
3. `term !== '常规'` → 非规时段
4. **兜底** → 正课 = 节数×（学科系数+班额系数），pay=0

> 关键：第 4 分支是兜底，任何「非字典类型 + term=常规」的 lesson_instances 都命中正课公式。这为「正课折算」提供了现成通道，**无需改计酬引擎**。

## 四、方案设计

### 4.1 计酬方式（pay_mode）扩展为三种

| pay_mode | 计酬公式 | 生成 lesson_instances 时 | 依赖字段 |
| --- | --- | --- | --- |
| `按次计酬` | 单价 × 节数 | `period_type` = 选定的按次计酬类型名 | 类型 ∈ period_type_pays |
| `固定折算` | 节数 × 固定系数 | `period_type` = 选定的折算类型名 | 类型 ∈ period_type_coefficients |
| `正课折算` | 节数 ×（学科系数+班额系数） | `period_type` = '正课'（非字典类型），`term`='常规'，`subject`=填报学科，`class_id`=填报班级 | 学科 + 班级 |

> 现有 `pay_mode` 取值是 `按次计酬` / `折算`。本次把「折算」重命名为「固定折算」语义不变，并新增「正课折算」。为兼容旧数据，`pay_mode='折算'` 视为「固定折算」。

### 4.2 私人定制课：三种形式如何组织

一对一/一对二/一对多是三种不同的单价，但共享「私人定制」这一业务。两种组织方式：

**方式 A（推荐）**：建**三个**课程任务（「一对一辅导」「一对二辅导」「一对多辅导」），每个任务的 `period_type` 固定对应一个类型，`pay_mode='按次计酬'`。教师按需要扫对应的码填报。简单、单价清晰、审核计酬直接。

**方式 B**：建**一个**「私人定制课」任务，在 `form_schema` 里加一个「形式」下拉字段（一对一/一对二/一对多），填报时选了形式后，审核计酬时把形式映射到对应的 `period_type`。灵活但需在计酬时做「表单字段→period_type」的动态映射，复杂度高。

> **本设计采用方式 A**，理由：单价不同本就该分开，方式 A 复用现有「任务固定一种计酬方式」的模型，零额外逻辑。若学校确实希望一个入口，再回退方式 B。

### 4.3 非周期课（心理/音乐）的正课折算

- 教务员建「课程申报任务」时选 `pay_mode='正课折算'`，填学科（如心理、音乐）。
- **教师填报时必选「班级」**（新增一个班级选择字段，因为班额系数依赖具体班级）。学科可由任务预设，也可让教师填。
- 审核通过生成 `lesson_instances`：`period_type='正课'`、`term='常规'`、`subject=学科`、`class_id=填报班级`、`source='course'`。
- 计酬自然命中 `computePay` 兜底分支 → 节数×（学科系数+班额系数），只记折算课时、课酬 0。

### 4.4 数据模型变更（小改）

`application_tasks` 无需新列——`pay_mode` 加一个取值即可，`subject` 已存在。需要确认 `form_schema` 支持「班级选择」字段类型（当前类型有 文本/日期/数字/下拉/多行文本，班级选择可复用「下拉」由任务预设班级列表，或新增「班级选择」类型）。

`applications` 需要新增 `class_id`（正课折算挂班用）。现有 `applications` 表无 class_id。

### 4.5 后端改动

- `validatePayConfig`：扩展支持 `pay_mode='正课折算'`（校验需有学科；班级由填报时给）。
- `POST /tasks`：`pay_mode` 接受 `按次计酬/固定折算/正课折算`。
- `POST /tasks/:taskId/apply`：正课折算任务填报时接收 `class_id`（+ 学科）。
- `PATCH /applications/:id/review`：审核通过时按 pay_mode 分三路生成 lesson_instances：
  - 按次计酬 → 现状（挂年级虚班，period_type=类型名）
  - 固定折算 → 现状（挂年级虚班，period_type=折算类型名）
  - **正课折算 → 新：挂填报的具体班级，period_type='正课'，subject=学科，term='常规'**
- 撤回/删除联动（source='course'）不变。

### 4.6 前端改动

- **桌面端** `Applications.jsx` Tab 2「课程申报」：
  - 创建课程时计酬方式三选：按次计酬 / 固定折算 / 正课折算。
  - 正课折算时：填学科（+ 提示教师填报时选班级）。
  - 私人定制课可加「一键创建三套（一对一/一对二/一对多）」快捷按钮（方式 A 的便利入口）。
- **手机端** `CourseApply.jsx`（分享填报页）：
  - 正课折算任务：动态表单里多一个「班级」选择（若 form_schema 含班级字段），填报时写 class_id。
- **移动端自主申报** `MobileApply.jsx`：移除「私人定制课」入口卡片（迁到课程申报），或保留但改为提示走课程申报。**默认移除**，与「迁到课程申报」结论一致。

## 五、实施步骤

1. **后端数据迁移**：`applications` 加 `class_id`（ensureColumn）。
2. **后端计酬**：`validatePayConfig` + `review` 分三路生成 lesson_instances（重点：正课折算挂具体班级）。
3. **后端填报**：`apply` 接收 class_id（正课折算）。
4. **桌面端**：计酬方式三选 + 私人定制三套快捷创建。
5. **手机端**：正课折算填报加班级选择；自主申报移除私人定制入口。
6. **验证**：建三类课程→填报→审核→统计中心/课酬报表核对三种计酬结果。

## 六、待确认

1. **私人定制三种形式**：采用方式 A（三个独立任务）还是方式 B（一个任务 + 形式下拉）？本设计默认方式 A。
2. **非周期课学科**：由教务员建任务时固定，还是教师填报时自填？本设计默认任务预设学科、教师只选班级。
3. **自主申报的私人定制入口**：直接移除，还是保留一个「去课程申报」的引导入口？
