# 常规检查功能完善设计（2026-10-06）

## 背景与问题

常规检查用于：课堂常规的日常检查、教学常规（备课本、听课本等）的周期性检查；「先听后上」隶属课堂常规。每个检查都要有自己的打分维度，每一次检查都要作为过程性资料沉淀，用于教师考核、备课组考核、教研组考核。

现有实现（`server/src/routes/inspections.js` + `client/src/pages/Inspections.jsx`）的问题：

1. **打分维度全局唯一一份**：课堂常规和备课本/听课本共用同一套打分项，不满足「每个检查有自己的维度」。
2. **「先听后上」是平级分类**，而非课堂常规下的子检查。
3. **「分类 / 模板 / 检查类型」概念混叠**：`category` 硬编码三类，模板只是分类下的一张表单，缺一个能承载「自己的维度 + 周期属性」的实体。
4. **周期属性缺失**：备课本/听课本是周期检查，但无任何日常/周期区分。
5. **过程性资料出口不足**：记录可存可查，但无「教师 / 备课组 / 教研组」聚合考核视图；备课组/教研组只有角色名，无实体。

## 已确认决策

| 决策点 | 结论 |
|---|---|
| 打分维度挂哪层 | **每个检查类型一套**（类型 = 模板，合一） |
| 检查类型组织 | **两级可配置**：大类 → 检查类型 |
| 备课组/教研组建模 | **两者结合**：默认按学科自动推导，可手动建组/命名/指定组长覆盖 |
| 周期检查表达 | **提交时标周期**（按日期自动算「本学期第几周」可改），不做排期计划 |
| 组考核指标 | **多维指标**（平均分 + 达标率 + 检查覆盖率） |

## 核心概念模型

把「检查模板」升格为「**检查类型**」，自带三个能力：

- **两级归类**：大类（预置「课堂常规」「教学常规」，可增删）→ 检查类型。`先听后上` = 课堂常规大类下的类型；`备课本`/`听课本` = 教学常规下的类型。
- **打分维度挂类型**：每个类型自带一套维度（含权重），不再全局共用。
- **周期属性**：`daily`（日常）/ `periodic`（周期）。周期类提交时附带「第 X 周」周期标记，供按周/月汇总。

## 数据模型

改动集中在三处，复用现有表，不推倒重来。

1. **`inspection_templates` → `inspection_types`**（重命名 + 增列）：
   - 增列 `category_id`（大类外键）、`cycle`（`daily`/`periodic`）。
   - `items`（检查项表单）原样保留。
   - 新表 `inspection_categories`（id/name/position），预置课堂常规、教学常规。

2. **打分维度按类型**：`inspection_score_settings` 增列 `type_id`。全局旧维度迁移到第一个检查类型下。检查记录 `inspections.score_data` 已存「维度名 → {score,weight,label}」快照，天然兼容维度增删，继续沿用。

3. **周期标记**：`inspections` 增列 `cycle_label`（如「第 5 周」）。周期类提交时按 `lesson_date` 自动算「本学期第几周」预填、可改；日常类留空。

4. **考核对象建模**（两者结合）：新增 `teacher_groups`（组）+ `teacher_group_members`（成员）。组类型 `教研组`（=学科）/`备课组`（=学科+年级）。默认自动推导：教研组 = 某学科全体教师，备课组 = 某学科某年级教师；允许手动建组、命名、指定组长、手动加成员。不建组时也能按学科/年级即时聚合。

## 配置入口与权限

- 检查类型结构（两级归类 + 维度 + 周期属性）由**管理员 / 教务处**统一配置（沿用 `roleRequired(...ADMIN_ROLES)`，与现状一致）。
- 日常巡查人只「提交检查」，不改结构。
- 预置常用类型：课堂常规巡查、先听后上、备课本检查、听课本检查，各带一套预置维度，减少首次配置成本。

## 考核汇总视图（新增「检查统计」Tab）

- **按教师**：各检查类型下的得分（实得/满分）、次数、平均分，可按时间区间/大类/检查类型筛选。
- **按组（备课组/教研组）**：组内教师个人得分先汇总，再聚合到组。多维指标：
  1. **平均分** — 组内教师个人得分（该教师所有记录实得/满分归一后的均值）的平均。
  2. **达标率** — 组内「个人得分 ≥ 达标线（默认 90，可配置）」的教师占比。
  3. **检查覆盖率** — 已检查教师数 ÷ 组内应检教师总数。
- **明细下钻**：任意汇总值下钻到具体检查记录列表，保证可追溯。
- 得分公式沿用：实得 = Σ(维度分×权重)、满分 = Σ(权重×100)；历史记录因快照已存维度结构，不受维度后续改动影响。

## 移动端

沿用 `MobileInspection.jsx`，只做「提交检查」，不做组配置和汇总看板（汇总在桌面端）。

## 迁移与兼容

- `inspection_templates` 升级为 `inspection_types`，老模板行归「课堂常规」大类、标 `daily`，检查项原样保留。
- 全局 `inspection_score_settings` 迁到第一个检查类型下（或留作「默认维度」供新类型复制）。
- `inspections.template_id` 改 `type_id`（加列 + 回填，保留旧列短暂兼容）。
- 老三类 `category` 值（课堂常规/先听后上/教学常规）映射到新两级结构，历史记录分类显示不塌。

## 实现顺序建议

1. 数据迁移：建 `inspection_categories`、`teacher_groups`/`teacher_group_members`，`inspection_templates` 升级 + 维度按类型 + `inspections` 增列。
2. 后端 `inspections.js`：类型 CRUD、按类型的维度、周期标记、检查统计聚合接口（教师/组）。
3. 前端 `Inspections.jsx`：类型配置页、提交页按类型带维度与周期标记、新增「检查统计」Tab。
4. 移动端 `MobileInspection.jsx`：适配按类型的维度与周期标记。

## 补充：检查配置（达标线 + 学期起始）

- 达标线与学期起始统一走 `app_settings`（key=`pass_line`/`semester_start`）。
- 接口 `GET/PUT /api/inspections/config`（管理员），前端「检查类型」Tab 顶部「检查配置」区管理。
- 统计页达标线框初始读配置值，可临时覆盖（显式传 `pass_line` 查询参数）；`stats/groups` 未传时回退 `passLineConfig()`（默认 90）。
- 达标线口径：组内「个人得分 ≥ 达标线」的教师占比。
