# 晚自习分年级计酬设计

日期：2026-10-08
状态：已实施

## 1. 背景与目标

现有「按次计酬」模型是**一个类型 = 一个单价**：`period_type_pays` 表存 `name → pay`，`computePay` 对按次计酬类型短路成「单价 × 节数」（折算课时 0）。晚自习此前只有一个价（基准 150 元/节）。

现实中晚自习存在**两种以上价格**，且区分维度是**年级**（高一/高二/高三晚自习价不同）。本次要在「改动最少」的前提下，让晚自习支持按年级分价，同时**保持「单价 × 节数」这条规则与教师申报流程完全不变**。

## 2. 头脑风暴结论（已确认）

价格区分维度 = **按年级**（用户确认）。据此对比了三套方案：

1. **把晚自习拆成「晚自习-高一/高二/高三」三个类型**——零后端改动，但教师申报时要自己选对类型，而年级信息他们已在「选班级」里选过，重复且极易填错，还会破坏防重复判定。否决。
2. **审核时把价格固化快照进记录**——抗后续改价，但违背系统「从字典实时重算」的既有哲学（这正是删除保护存在的理由），改动大。否决。
3. **给 `period_type_pays` 增加「按年级覆盖价」**——`computePay` 里 `price = 分年级价 ?? 基准价`，年级从 `class_id` 自动推导，教师申报流程零改动。**采纳**。

关键可行性：`computePay` 的所有调用点（`stats.js` 按日统计/导出/财务、`schedules.js` 课表统计/导出）的 `r.class_id` 都齐全，`classes.grade` 是现成字段。晚自习挂**行政班**、答疑挂**年级虚班**，两者 `classes` 记录都带 grade，故年级都能自动识别，教师无需额外选择。

## 3. 数据模型变更

新增一张表（通用，任何按次计酬类型都能加年级价，当前仅晚自习用）：

```sql
CREATE TABLE period_type_grade_pays (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  period_type TEXT NOT NULL,
  grade TEXT NOT NULL,
  pay REAL NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE UNIQUE INDEX idx_period_type_grade_pays ON period_type_grade_pays(period_type, grade);
```

- `period_type` 非外键（与 `period_type_pays.name` 逻辑对应），删除类型时由应用层联动清理（见第 5 节）。
- 年级值需与 `classes.grade` 完全一致（高一/高二/高三）。
- 未设覆盖价的年级，回退 `period_type_pays.pay` 基准价。

## 4. 后端改动

### `server/src/context.js`（计酬核心）

- `loadContext` 的 `classMap` SELECT 补 `grade` 列。
- 新增 `periodTypeGradePays`：`Map<类型, Map<年级, 单价>>`，从新表加载。
- 新增两个 ctx 助手：`gradeOf(cid)`（班级→年级）、`gradePayOf(type, grade)`（覆盖价，无则 `undefined`）。
- `computePay` 按次计酬分支：`pay = gradePayOf(...) ?? periodTypePays.get(type) ?? 0`，再 `× count`。规则「单价 × 节数」不变。

### `server/src/routes/stats.js`（接口 + 口径）

- `GET /stats/type-pays/grade-pays` — 列出所有分年级覆盖价，附 `base_pay`（类型基准价）。
- `PUT /stats/type-pays/grade-pays` — 批量保存（按 id 更新，无 id 新增；同类型+同年级幂等更新）。
- `DELETE /stats/type-pays/grade-pays/:id` — 删除单条。
- 删除按次计酬类型时联动 `DELETE FROM period_type_grade_pays WHERE period_type = ?`，避免遗留孤儿价。
- `financial-report` / `financial-pack` 的口径说明 sheet，在「按次计酬类型」段补「`某类型 分年级：高一X元，高二Y元…`」一行。

### `server/src/db.js`

- 主 schema 加 `period_type_grade_pays` 建表语句（`CREATE TABLE IF NOT EXISTS` + 唯一索引，幂等，旧库自动补建）。

## 5. 前端改动（`client/src/pages/Stats.jsx`）

- `load()` 增加并行请求 `GET /stats/type-pays/grade-pays`，存入 `gradePays` state。
- 新增 `setGradePay` / `addGradePay` / `saveGradePays` / `delGradePay` 四个 handler（与现有 typePays/typeCoefs 同构）。
- 「统计配置」Tab 的「按次计酬类型」卡片后新增**「分年级课酬」卡片**：表格列 = 类型（下拉，来自 typePays）/ 年级（文本框）/ 单价（数字）/ 删除；可增删改并保存；下方说明文字解释覆盖优先级与年级需匹配班级信息。

## 6. 不改动的部分（改动最小化的关键）

- **教师申报流程零改动**：`MobileApply.jsx` / `Applications.jsx` 的晚自习填报、审核、防重复判定、生成 `lesson_instances` 逻辑全部不动——价格由后端按 `class_id → grade` 自动定价。
- **汇总/导出/财务/勾稽校验的列结构不变**：`periodTypePays` Map 值仍是数字（基准价），`buildFinancial`、`financial-check` 的按类型分列/合计逻辑不变；仅每节课的 `pay` 金额按年级覆盖价计算。

## 7. 验证

- 后端 `node --check` 三文件通过。
- 单元级：`computePay` 对「晚自习」分别取高一行政班 / 高三行政班，返回覆盖价 100 / 基准价 150；「答疑」无覆盖仍 30。
- 前端：重建后「统计配置」出现「分年级课酬」卡片，可增删改保存，删除类型联动清理覆盖价。

## 8. 遗留与边界

- 覆盖价年级名必须与班级信息里的 `grade` 一致，否则不生效（回退基准价）——卡片说明已提示。
- 若某类型未来要按「班级类型 / 节次」分价，本表可扩展 `grade` 列语义或另加维度列；当前 YAGNI，只做年级。
