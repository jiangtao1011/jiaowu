# 移动端（手机 / PAD）功能与 UI 设计

> 日期：2026-10-05 · 状态：头脑风暴定稿（待实现）

## 背景与目标

教务管理系统已有完整桌面端（Node/Express + React），移动端目前只有一个独立自主申报页 `/apply`。
本次为**手机与 PAD** 规划一套完整的移动端界面，覆盖教师 / 年级组长 / 教务员（教务处、admin）三类角色，
复用现有后端与数据表，目标是：操作方便、布局合理、配色和谐、去「AI 味」、登录更省事。

## 已确认的核心决策

1. **形态**：响应式 + 独立移动页面（复用后端与样式），不做 PWA / 独立小程序。
2. **登录**：记住我（长期 token）+ 扫码登录（局域网内手机扫码直达）。
3. **信息架构**：统一移动端壳 + 底部导航，按角色动态显示功能入口。
4. **课时查询**：按身份区分视角（教师看自己，教务员/组长看全体并可下钻）。
5. **通知提醒**：应用内未读角标 + 红点（不接外部推送，局域网难落地）。
6. **视觉**：现代明亮风（浅底白卡、大圆角、留白、低饱和主色），系统字体、线性图标，克制去 AI 味。

## 角色与功能矩阵

| 底部 Tab | 教师 | 年级组长 | 教务员/教务处/admin |
|---|---|---|---|
| 首页 | 今日课务 + 待办提醒 | 本年级概览 + 待办 | 教务总览（待审核数等） |
| 申报 | 答疑 / 晚自习自主申报 | 批量申报(本年级) + 自己申报 | 批量申报(全年级) |
| 课时 | 我的课时 / 课酬 / 标准 / 系数 | 本年级 + 自己 | 全体统计可下钻 |
| 通知 | 收通知 + 回复 | 同左 | 通知管理(发布) |
| 我的 | 个人信息 / 退出 | 同左 | 同左 |

教研组长 / 备课组长按教师处理（后续可开放本组统计）。

## 页面与交互

### 移动端壳 `MobileShell`
- 顶部简洁标题栏（当前页标题 + 可选返回/更多），底部 5 个 tab。
- PAD：同一套页面用更宽栅格（卡片两列），不另做一套。
- 设备分流：登录后按 `width < 768` 或 UA 跳 `/m`；桌面端侧边栏「自主申报」直达 `/apply` 保持不变。

### 首页（今日待办提醒）
- 教师：今日要上的课（来自 `lesson_instances` 或课表）、我的待办（待审核申报、未读通知）。
- 教务员/组长：待审核申报数、待审核通知回复数、今日校历标记、未来工作提醒（复用 dashboard 数据）。

### 申报
- 复用并改造现有 `/apply` 的交互，迁入移动壳。
- 教师：答疑（年级级）+ 晚自习（班级级）。
- 年级组长 / 教务员：批量申报（同一天·同类型·多选教师，沿用已实现的交互）。

### 课时（按身份区分视角）
- 教师：`GET /stats/summary?teacher_id=<me>` → 总课时 / 折算课时 / 课酬估算，按类型拆分，可展开明细。
- 组长/教务员：全体视角，筛选年级/教师，下钻单个教师。
- 标准与系数：只读展示学科系数、班额系数、时段课酬标准、按次计酬单价（复用 `coefficients`、`type-pays`）。

### 通知（未读角标）
- 只显示已发布通知（`publish_status='published'`，当前 `GET /notices` 未过滤，需补）。
- 底部「通知」tab 带未读红点（新接口 `GET /notices/unread-count`）；点开即标记已读（复用 `notice_reads`）。
- 登录用户回复走 `notice_replies`（进入待审核）。

### 我的课表
- 教师移动端看本周 / 下周自己的课表（复用 `GET /schedules?teacher_id=` 或按日展开）。

### 代课调课申请
- 教师移动端发起代课/调课申请，教务员处理（复用 `schedule_changes` / `POST /schedules/adjust`，需把当前仅管理员的权限改为「教师申请 → 教务员审核」的两段式，或新增申请表）。

### 常规检查录入
- 移动端选课（日期+班级+节次自动带出教师/科目）+ 拍照上传 + 打分（滑条），复用 `inspections` 表与 `schedule-lookup` 接口，优化触屏体验。

## 登录（记住我 + 扫码）

- **记住我**：勾选后发长期 token（如 30 天），否则维持 7 天；前端 `localStorage` 已持久化。
- **扫码**：桌面端已登录时生成一次性二维码（`qrcode` 依赖已存在），手机扫码 → `/login/scan?code=…` → 换正式 token 登录。

## 视觉规范（现代明亮 + 去 AI 味）

- 背景浅灰，卡片纯白，大圆角（12–16px），触控目标 ≥ 44px。
- 主色：在墨绿 `#167d6f` 基础上提亮为偏青的绿（或克制蓝青），点缀色极少。
- 字体：系统栈（PingFang SC / -apple-system / sans-serif），线性图标。
- 去 AI 味：真实业务名词、清晰层级；避免渐变堆叠、emoji 图标、套话文案、无意义的装饰性元素。

## 后端改动清单（实现时）

1. `GET /notices` 加 `publish_status` 过滤；新增 `GET /notices/unread-count`（按 `notice_reads` 统计当前用户未读）。
2. `GET /stats/summary` 支持 `teacher_id` 参数（个人视角）。
3. 扫码登录：新增一次性 code 签发与兑换接口（`POST /auth/scan-code`、`POST /auth/scan-login`）。
4. 「记住我」：`signToken` 支持不同过期时长（前端传 remember）。
5. 代课/调课：视首版范围决定是否改为「申请-审核」两段式（新增申请表或复用现有 adjust）。

## 范围建议（MVP 边界）

首版（MVP）先交付：移动壳 + 首页待办 + 申报 + 课时查询 + 通知（未读角标）+ 登录（记住我/扫码）+ 我的课表。
代课调课申请、常规检查录入为第二批（涉及权限模型与触屏优化，量较大）。
