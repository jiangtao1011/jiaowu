# 教师自主申报：答疑（年级级）+ 晚自习（班级级）设计

日期：2026-10-03
状态：头脑风暴定稿，待实施

## 1. 背景与目标

现有「课务申报」是一个通用表单，把答疑、晚自习、晚练、自定义类型混在一起：年级是自由文本、班级是全校下拉、教师靠手动选择，没有「自主申报」的身份语义，手机端（侧边栏折叠 + 密集表格）体验差。

本次新增：**老师在手机上自主申报「答疑」和「晚自习」两类临时课务**，操作便捷、界面美观。核心差异约束：

- **答疑课**：针对**年级**，不针对某个班。
- **晚自习**：针对**某个具体班级**（该老师代课年级的行政班）。

时间形态只做**临时单次**（某天 + 节数）。每周固定的晚自习继续走现有桌面端课表导入 / 固定排班路径，不在此范围。

## 2. 头脑风暴结论（已确认）

1. **身份映射**：登录账号（`users`）绑定教师档案（`teachers`），登录即自动带出「我是谁 + 我的学科」，无需手动选自己。
2. **手机形态**：新增**独立移动端页面**（大卡片 + 大按钮），非改造现有表格页。
3. **审核流程**：老师提交后**需教务处审核**，通过才计酬（复用现有 pending→approved/rejected→withdrawn 状态机）。
4. **时间形态**：只做**临时单次**（选日期 + 节数）。
5. **晚自习班级范围**：老师可选 **代课年级的行政班**。
6. **手机范围**：只做**申报 + 我的记录**，不扩展其它工作台内容。

## 3. 身份打通：账号 ↔ 教师档案

两张表现在无关联（`users` 与 `teachers`），这是自主申报的前提。

- `users` 表新增列 `teacher_id INTEGER REFERENCES teachers(id)`（`ensureColumn` 迁移，可空；非教师角色留空）。
- 账号管理（`Users.jsx` / `routes/users.js`）：创建/编辑「教师」角色账号时，可下拉选择绑定的教师档案；`PATCH /users/:id` 支持 `teacher_id`。
- 登录后 `req.user.teacher_id` 即当前教师身份；后端据此解析「我」。
- 兼容：已有教师账号若无绑定，首次进入移动申报页提示「请联系教务员绑定教师档案」，或回退为手动选择教师（保留旧行为兜底）。

## 4. 答疑：年级级（关键技术）

`lesson_instances.class_id` 是 NOT NULL，统计/导出 SQL 为 `JOIN classes ON c.id = li.class_id`（INNER JOIN），答疑不能把 class_id 留空（会被丢弃）。

**方案：年级虚拟班（走班复用）**。为每个年级建一个虚拟班级，复用现有「走班（合班）」模型：

- `classes` 新增一条记录：`type='走班'`、`name='高一年级'`、`grade='高一'`，用 `class_members` 挂该年级所有**行政班**（`type='行政班'` 且 `grade` 相同）。
- 答疑的 `lesson_instances.class_id` 指向该年级虚拟班。
- 优点：class_id NOT NULL 满足、JOIN 不丢、统计/导出自然显示「高一年级」、班额自动 = 年级行政班人数之和（答疑按次计酬短路，实际不吃班额系数，仅用于展示与概念一致）。
- 虚拟班不参与真实课表、不在晚自习班级选择里出现；在班级列表用 `name` 前缀或单独标识区分，避免与真实班混淆。

**年级来源（老师的可选答疑年级）**：从课表推导 `SELECT DISTINCT c.grade FROM schedules s JOIN classes c ON c.id = s.class_id WHERE s.teacher_id = ?`；为空时回退全校年级枚举（高一/高二/高三）。

## 5. 晚自习：班级级

- `class_id` 指向**真实行政班**（`type='行政班'`）。
- 可选班级 = 老师代课年级下的所有行政班（年级由第 4 节同源推导）。
- 按次计酬：`computePay` 走 `periodTypePays` 短路，课酬 = 单价（晚自习默认 150 元/节）× 节数。

## 6. 数据模型变更汇总

| 变更 | 说明 |
| --- | --- |
| `users.teacher_id` | 新增列，账号→教师档案 |
| `classes` 年级虚拟班 | 每年级一条 `type='走班'` + `class_members` 挂行政班 |
| `qna_lessons` | 复用，`class_id` 对答疑存年级虚拟班 id，晚自习存行政班 id，`period_type` 区分「答疑/晚自习」 |

无需新增业务表；答疑/晚自习仍是 `qna_lessons` 里 `period_type` 不同的两条记录，共享现有审核与计酬链路。

## 7. API 设计（`routes/applications.js` 扩展）

- `GET /api/applications/self` — 返回 `{ teacher_id, subject, qna_grades[], evening_classes[], my_records[] }`：当前登录教师的身份、可选答疑年级、可选晚自习班级、我的申报记录。
- 复用 `POST /api/applications`（填报，`class_id` 由前端按类型传年级虚班/行政班 id）、`PATCH /:id`、`DELETE /:id`、`PATCH /:id/review`、`PATCH /:id/withdraw`。
- 现有 `GET /api/applications?status=` 加 `teacher_id` 过滤参数（供「我的记录」）。

审核通过计酬沿用现有逻辑：有 `date` 的临时填报生成 `lesson_instances`（`source='qna'`），答疑挂年级虚班、晚自习挂行政班；撤回/删除联动删除上课记录。

## 8. 移动端 UI

- 新增独立页面 `client/src/pages/MobileApply.jsx`，路由 `/apply`，手机收藏 `http://<host>:5173/apply` 直达。
- **布局**：顶部品牌条 + 大标题；下方两个大入口卡片——「申报答疑」「申报晚自习」；再往下「我的申报」记录流。
- **申报答疑卡片**：自动显示「我 + 学科」；选年级（大按钮组，而非长下拉）、选日期（`<input type="date">`，默认今天）、选节数（+/- 步进器）、内容说明（可选）、大号「提交」按钮。
- **申报晚自习卡片**：自动显示「我 + 学科」；选班级（我代课年级的行政班，卡片式选择）、选日期、节数、提交。
- **我的记录**：列表卡片，每条显示类型徽标 + 日期 + 节数 + 状态徽标；待审核可编辑/删除，已通过显示计酬信息。
- 样式：复用墨绿主色 `#167d6f`，大触控目标（≥48px）、卡片圆角阴影、底部留白；新增 `.mapply-*` 样式追加到 `index.css`。
- 移动端优先但桌面可用；`Layout` 侧边栏「日常事务」组加「自主申报」入口（教师角色高亮）。

## 9. 审核与权限

- 复用现有状态机与权限：填报人可编辑/删除自己**待审核**记录；管理员（教务员/教务处/admin）审核（通过/驳回）、撤回已通过记录。
- 身份由 `req.user.teacher_id` 自动代入，前端不再提供「教师」下拉。

## 10. 迁移与兼容

- 新增 `users.teacher_id`、年级虚拟班，均为增量迁移，不影响已有数据与统计。
- 现有「按次计酬申报」通用表单保留（桌面端仍可批量导入 / 手动填报），新增移动端是**面向教师的快捷入口**，二者写同一张 `qna_lessons` 表，数据互通、审核统一。

## 11. 实施阶段（建议顺序）

1. **后端身份 + 数据**：`users.teacher_id` 迁移；账号管理支持绑定教师档案；`GET /applications/self` 聚合接口（身份/年级/班级/我的记录）。
2. **年级虚班**：建年级虚拟班（`type='走班'`）与 class_members；答疑审核通过生成 `lesson_instances` 时挂年级虚班；统计/导出验证不丢记录。
3. **移动端页面**：`MobileApply.jsx`（答疑卡 + 晚自习卡 + 我的记录）+ 路由 + 导航入口 + 样式。
4. **验证**：端到端跑通「教师登录→申报答疑→教务审核→统计中心出现计酬」，及「晚自习→行政班计酬」，手机窄屏截图确认界面。
