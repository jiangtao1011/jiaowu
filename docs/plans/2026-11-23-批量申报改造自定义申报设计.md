# 批量申报改造为「自定义申报」设计

> 2026-11-23 · 教务管理 · 移动端课务申报

## 背景

手机端「批量申报」目前只把**按次计酬**类型（`period_type_pays`：晚自习/答疑/晚练/晚晚练/一对一/一对二/一对多）加入类型选择，遗漏了**按课时折算**类型（`period_type_coefficients`：早自习/竞赛/培优/监考·标准/监考·加时/监考·长时）。

本改造把「批量申报」升级为「自定义申报」：类型来源 = 按次计酬字典 + 折算字典（不含正课），让教务员/年级组长能帮教师批量录入折算型课务（竞赛、培优、监考等）。

## 已确认决策

1. **形态**：保持「多教师批量」——选一个公共类型 + 日期 + 节数/课时数，勾选多位教师一次提交。
2. **早自习**：纳入自定义申报（不排除）。
3. **折算类型的课时数**：始终可填（不受「显示节数」开关控制，因为折算 = 课时数 × 系数，课时数是关键输入）。
4. **折算类型的班级维度**：年级级（不选班），挂年级虚班；不精确到班。

## 计酬口径（现状，无需改）

`context.js` 的 `computePay` 已按 `period_type` 分派：
- 命中 `period_type_coefficients` → 折算课时 = 节数 × 系数，课酬 0（折算型不计钱）。
- 命中 `period_type_pays` → 折算 0，课酬 = 单价（含分年级覆盖）× 节数。

因此只要申报记录里的 `period_type` 正确写入「竞赛/培优/监考」等名字，计酬自动正确。**当前唯一缺口是 `validPeriodType` 不认折算字典**，会把折算类型回退成「答疑」导致计酬错误——这是本次的核心修复点。

## 后端改动（applications.js）

1. **`validPeriodType`**：改为「命中按次字典 或 折算字典 即保留」，删除对「早自习」的特判（早自习本就在折算字典里）。
2. **新增 `isCoefficientType(name)`**：判断某类型是否折算类型（查 `period_type_coefficients`）。
3. **`insertQnaPending`**：折算类型（含早自习）未指定班级时回填该年级虚班——从「仅早自习」放宽到「所有折算类型」。
4. **`findDuplicate`**：折算类型按**年级级**判重（与答疑/早自习同支），不再落入「年级+班级」分支。
5. **`GET /batch-context`**：返回 `typePays` 之外，新增 `typeCoefs`（折算类型字典 `{id,name,coefficient}`），供前端下拉。

## 前端改动（MobileApply.jsx）

批量申报表单（`mode === '批量'`）：

1. **类型选择**：合并展示两组 chips —— 按次计酬（`typePays`，显示「×元/节」）+ 按课时折算（`typeCoefs`，显示「×系数」），带分组小标签。
2. **课时数/节数字段**：折算类型**始终显示**（label「课时数」）；按次类型受 `showPeriodCount` 开关控制（label「节数」）。
3. **班级字段**：折算类型**隐藏**（年级级）；按次类型保持现状（选填）。
4. **提交**：折算类型强制 `class_id = null`（挂年级虚班）。

类型类别判断：`batchCtx.typeCoefs.some(t => t.name === batchType)` → 折算类型。

## 边界与注意

- 「早自习」既出现在折算字典、又是历史上有单独入口的类型，本次统一进折算组展示，不破坏其计酬（仍是折算型）。
- 正课（常规课表）明确**不进入**自定义申报，因为正课走课表导入，不走申报。
- 年级组长受 `managed_grade` 锁定，行为不变。
