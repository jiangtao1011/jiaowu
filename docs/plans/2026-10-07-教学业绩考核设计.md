# 教学业绩考核设计（备课组各率 + 配置化考核 + 教师档案固化）

日期：2026-10-07（头脑风暴定稿，含「其它成绩类型」补充）

## 一、目标与范围

教学业绩考核模块，解决「按备课组的考试成绩各率，对教师、备课组、教研组进行业绩考核」。四个关键词：**率由人录、考核可配、多考加权、档案固化**。

核心结论先行：

| 决策点 | 结论 |
|--------|------|
| 各率怎么来 | **人工录入**，系统不内置「原始成绩 → 各率」计算 |
| 成绩文件 | 只做**留档附件**，不做分析（分析交给桌面版 Claude/WorkBuddy 技能） |
| 考核结构（率） | **可配置**：各率加权合成单次考核分（默认 A率×0.6 + B率×0.4） |
| 考核结构（考试） | **可配置**：多种考试类型加权合成学期分（默认期末为主，学考等可选） |
| 学期考核口径 | **期末 + 可选其它成绩类型**，按类型权重加权，无该类型自动只算期末 |
| 考试类型 | **可扩展字典**（期末/期中/月考/学考/会考/自定义），每类可设权重 |
| 录入粒度 | **备课组单一粒度**（教师/教研组引用备课组数据） |
| 考试组织 | **整场考试一个实体**（一场考试覆盖多备课组） |
| 文件存档粒度 | **考试 × 备课组** |
| 下载权限 | **管理层可下**（管理员/教务处/教研组长/备课组长） |
| 教研组考核分 | **备课组考核分的均值** |
| 教师查看 | 普通教师可在线查看**本组**成绩 |
| 教师档案 | 各率固化为教师档案，**手动固化**（方案 A，学期级） |

## 二、现状与复用

本模块尽量复用已有地基，不重复造轮子：

1. **备课组/教研组建模**：`teacher_groups`（type=备课组/教研组，subject/grade/leader_id/is_auto）+ `teacher_group_members`。自动推导逻辑已在 `inspections.js` 的 `/groups` 里实现（教研组=学科、备课组=学科+年级，来源 `schedules JOIN classes.grade` 与 `teachers.subject`）。**业绩考核与常规检查共用同一套组**，保证数据一致。
2. **作用域**：`server/src/scope.js` 的 `visibleTeacherIds` / `visibleGrades` 已按角色过滤。本模块需**新增组级作用域** `visibleGroups(user)`（见下）。
3. **配置存储**：`app_settings`（key/value 均 TEXT）已用于 `semester_start`；率权重存这里。考试类型字典用独立表（需 CRUD，类比 `period_type_pays`）。
4. **时间版本/固化思想**：与课酬 `payroll_snapshots`（财务审核后归档固化）、课表 `effective_from/to` 一致——「变化前的统计不受影响」。

## 三、数据模型（5 张新表）

### ① `exam_types`（考试类型字典，可扩展）

```
id, name（UNIQUE：期末/期中/月考/学考/会考/自定义…）,
weight（REAL，参与学期考核的权重，0=不参与仅留档）,
position（排序）, active,
created_at
```

- 预置：期末(1.0)、期中(0)、月考(0)、学考(0.5 示例，可改)。
- `weight` 是「该类型相对学期考核的权重」，参与类型按权重**归一化**合成学期分（见下）。
- 类比 `period_type_pays`（按次计酬类型字典），提供 `GET/POST/PATCH/DELETE /exam-types`。

### ② `exams`（考试实体，一场一条）

```
id, name（如「高一高二期中考试」）, semester（学期文本，如「2025-2026 第二学期」）,
exam_type（引用 exam_types.name）, exam_date, note,
created_by, created_at
```

- `exam_type` 存字典 name（与 `period_type` 存 name 字符串的既有约定一致）。
- 一学期可有多种类型各一场（一场期末 + 一场学考等）。

### ③ `exam_scores`（备课组各率，考试 × 备课组 一条）

```
id, exam_id（REFERENCES exams）, group_id（REFERENCES teacher_groups）,
rate_a, rate_b, rate_c, rate_d, rate_e（均 REAL，百分比 0~1，人工录入）,
total_count（参考人数，可选）, avg_score（均分，可选，仅展示不参与考核）,
UNIQUE(exam_id, group_id)
```

- `rate_x` 存小数（0.45 表示 45%），录入界面按百分比填，后端除 100 存。
- C/D/E 率录了也存（用户要求 A/B/C/D/E 五率都记录），考核默认只用 A+B（率权重可配成含更多率）。

### ④ `exam_files`（成绩文件留档，考试 × 备课组 一条）

```
id, exam_id, group_id, filename, stored_path, mime,
uploaded_by（REFERENCES users）, uploaded_at
```

- 复用 `multer` 上传，存储路径沿用现有 `UPLOAD_DIR` 约定。
- 一个考试 × 备课组可多个文件（一组成绩可分多文件），`exam_id+group_id` 不加唯一约束。

### ⑤ `teacher_assessment_records`（教师业绩档案，学期级快照）

```
id, teacher_id（REFERENCES teachers）, group_id（REFERENCES teacher_groups）,
semester, score（REAL，学期考核分，两层加权后的最终分）,
detail（TEXT JSON，参与的各考试类型原始率快照 {期末:{rate_a..e}, 学考:{...}}，供追溯）,
locked_by（REFERENCES users）, locked_at, created_at,
UNIQUE(teacher_id, semester, group_id)
```

- 一位教师若跨多个备课组（跨年级/跨学科任课），每学期每组各生成一条档案；「教师考核分」取其所属**各备课组考核分的均值**（与教研组同口径）。
- 档案存**学期级**最终分 + 参与类型的原始率快照（detail），不是单次考试级。

## 四、考核分计算（两层加权）

### 配置（考核结构可配，分两处）

**第一层——率权重**（`app_settings`，key=`assessment_config`）：

```json
{
  "rate_weights": { "a": 0.6, "b": 0.4, "c": 0, "d": 0, "e": 0 },
  "full_score": 100
}
```

**第二层——考试类型权重**（`exam_types.weight`）：期末=1.0、学考=0.5（示例）、期中/月考=0。

### 第一层：率 → 单次考试考核分

```
单次考核分(考试) = Σ( rate_x × 100 × rate_weights[x] )   // rate_x 为 0~1，×100 变 0~100 分
例：A率=0.45、B率=0.38 → 45×0.6 + 38×0.4 = 42.2 分
```

### 第二层：多类型 → 学期考核分（**归一化加权**）

```
学期考核分(备课组) = Σ( 单次考核分_t × weight_t ) / Σ( weight_t )
   其中 t 遍历「该组该学期在 exam_scores 里有数据、且 weight_t > 0」的考试类型
```

- **归一化**保证「可选项」语义：某组某学期只有期末（没录学考），分母 = 期末 weight，学期分 = 期末分，不受其它类型权重影响；录了学考才按 `期末:学考` 比例加权。
- 例：期末 42.2 分、学考 50 分，权重 1.0 / 0.5 → 学期分 = (42.2×1.0 + 50×0.5) / 1.5 = 44.8 分。

### 层级引用

| 层级 | 学期考核分来源 |
|------|-----------|
| 备课组 | 上述两层加权（期末 + 可选的其它类型） |
| 教师 | 所属**各备课组学期考核分的均值**（教师可跨组） |
| 教研组 | 该学科下**各备课组学期考核分的均值** |

> 均**实时算、不落库**（落库的只有率快照在档案 detail 里）。改率权重或类型权重，未固化的考核分跟着变。

## 五、权限矩阵

复用 `scope.js`，新增组级作用域 `visibleGroups(user)`：
- 教研组长 → `subject=本学科` 的所有组
- 备课组长 → 自己担任 `leader_id` 的组（或 `group_members` 含自己的组）
- 年级组长 → `grade=managed_grade` 的组
- 教师 → 自己所在的备课组
- 管理员/教务员/教务处 → 全量

| 操作 | admin/教务员/教务处 | 教研组长 | 备课组长 | 年级组长 | 教师 |
|---|---|---|---|---|---|
| 建考试、录各率 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 传成绩文件 | ✅ | 本学科 | 本组 | ❌ | ❌ |
| 在线查看成绩 | ✅ 全量 | 本学科 | 本组 | 本年级 | 本组 |
| 下载成绩文件 | ✅ 全量 | 本学科 | 本组 | ❌ | ❌ |
| 看考核汇总 | ✅ 全量 | 本学科 | 本组 | 本年级 | 自己 |
| 配考试类型/率权重 | ✅ | ❌ | ❌ | ❌ | ❌ |

> 教师「下载」明确关闭，只能在线查看（管理层可下）。教师查看的入口是「我的业绩档案」。

## 六、教师档案固化流程（手动，方案 A，学期级）

1. 教务员建考试、录各备课组的率（期末 + 可选的学考等，可反复改，此时**不影响**档案）。
2. 某学期所有参与类型录完后，教务员点「固化本学期档案」——系统按 `teacher_group_members`，对每位教师所属备课组做两层加权，得学期考核分，连同各类型原始率快照进 `teacher_assessment_records`，写 `locked_at/locked_by`。
3. 固化后，教师在线查看的是**档案**（快照），不是实时率；后续改率/改权重**不影响已固化档案**。
4. 若需重固化（如录错了）：提供「重新固化」操作，删除该学期该批档案再重建（带确认，写审计日志）。

## 七、API 接口清单（拟挂 `/api/assessment`，新路由 `server/src/routes/assessment.js`）

| 方法/路径 | 作用 | 权限 |
|---|---|---|
| `GET/POST/PATCH/DELETE /exam-types` | 考试类型字典 CRUD | 读登录、写 ADMIN_ROLES |
| `GET /exams?semester` | 考试列表 | 登录 |
| `POST /exams` | 建考试 | ADMIN_ROLES |
| `PATCH /exams/:id` / `DELETE /exams/:id` | 改/删考试 | ADMIN_ROLES |
| `GET /exams/:id/scores` | 取某考试各备课组率（含组名/学科/年级） | 按作用域过滤组 |
| `PUT /exams/:id/scores` | 批量写各率（body 传 `[{group_id, rate_a..e}]`） | ADMIN_ROLES |
| `POST /exams/:id/files`（multipart，`group_id`） | 传成绩文件 | ADMIN_ROLES + 组长（作用域校验） |
| `GET /exams/:id/files` | 列文件 | 按作用域 |
| `GET /files/:fileId/download` | 下载文件 | ADMIN_ROLES + 组长 |
| `GET /config` / `PUT /config` | 读/写率权重配置 | ADMIN_ROLES |
| `GET /summary?semester` | 学期考核汇总（备课组/教师/教研组三层） | 按作用域 |
| `GET /my-record?semester` | 教师看自己的业绩档案 | 登录（本人） |
| `POST /semesters/:semester/archive` | 固化本学期档案（手动） | ADMIN_ROLES |
| `POST /semesters/:semester/rearchive` | 重新固化（删旧重建） | ADMIN_ROLES |

> 说明：`PUT /exams/:id/scores` 用「全量替换」语义（body 传该考试全部要保存的组率），简单幂等，与检查打分维度 `PUT /score-settings` 一致。

## 八、前端界面（桌面端 `client/src/pages/Assessment.jsx`）

新侧边栏入口「教学业绩」，三个 Tab：

1. **考试与成绩**：考试列表（按学期分组）→ 点开某考试 → 左侧备课组列表（按年级+学科分组，复用移动端常规检查的折叠分组样式思路），右侧逐个填 A/B/C/D/E 率 → 顶部实时显示该考试考核分预览 → 传成绩文件（按组）。
2. **考核汇总**：按学期筛选，三张表（备课组 / 教师 / 教研组），显示各率 + 学期考核分（两层加权）+ 排名（可选），按作用域过滤。教师视角只显示「我的档案」。
3. **考核配置**：两区——① 率权重（A/B/C/D/E 各一个权重输入，默认 0.6/0.4/0/0/0）+ 满分；② 考试类型字典（增删类型、设权重），管理员可见。

**移动端**：首版仅做「教师查看我的档案」（`MobileAssessment.jsx` 挂在 `/m` 下，只读）。录入/配置/汇总在桌面端。

## 十、实施顺序建议

1. **数据表 + 作用域 + 考试类型字典 + 考试/成绩 CRUD**（建类型、建考试、录各率、传文件、下载）——先让「录入」跑通。
2. **两层加权计算 + 率权重配置 + 汇总页**——把「考核」跑通（单次加权 + 多类型归一化加权 + 三层引用）。
3. **教师档案固化（学期级）+ 教师查看入口（含移动端）**——把「固化 + 教师自助查」闭环。
4. **成绩分析技能**（桌面版 Claude/WorkBuddy 读成绩文件）——放在主线之后，独立迭代。
