# 值日申报独立重构设计

日期：2026-11-28

## 一、背景与目标

现有值日申报寄生在「自主申报」（qna_lessons）里：教师在手机端自主申报值日，走「年级组长一审 → 课程中心终审」，通过后按档位金额计酬。

经头脑风暴确认，值日的真实业务是：

> 值日老师是**早自习出勤、晚自习答疑考勤**的主要执行角色。管理员/组长先安排值日排班；值日老师履职当天，用现有「常规检查」系统记录考勤，再上传**值日日报截图**作为履职凭证；日报经两级审批通过后，才给值日补贴。

因此值日要从「教师自主申报」里**独立出来、去耦合**，变成「安排 + 履职日报 + 审核计酬」的闭环。

### 已确认的关键决策

| 维度 | 决策 |
|------|------|
| 录入方 | 桌面端管理员/教务员/年级组长统一安排（教师不能自己报值日） |
| 形态 | 临时单次 + 固定星期排班，两者都支持 |
| 值日类型 | 不细分早/晚，统一「值日」；金额由安排时选档位（沿用现有 duty_pay_tiers） |
| 考勤记录 | 走现有「常规检查」系统，值日功能只管「履职日报截图」 |
| 计酬时机 | **日报通过后才计酬**（安排时不计酬） |
| 日报审批 | 沿用现有两级审批：年级组长一审 → 教务主任/admin 终审 |
| 手机端 | 值日老师查看自己的排班 + 提交日报；审核角色可审日报 |

## 二、数据模型

新建三张表（复用现有 `application_attachments` 的磁盘附件模式、`qna_lessons` 的状态机与两级审批字段约定）：

```sql
-- 值日排班：每条 = 某教师某天值日（临时/固定都最终落成具体日期）
CREATE TABLE duty_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  teacher_id INTEGER NOT NULL REFERENCES teachers(id),
  grade TEXT,                     -- 年级（挂年级虚班计酬用）
  duty_date TEXT NOT NULL,        -- 值日日期 YYYY-MM-DD
  pay_amount REAL NOT NULL,       -- 档位金额（安排时选定）
  note TEXT,
  created_by INTEGER REFERENCES users(id),
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- 值日日报：老师履职后提交截图 + 文字，两级审批
CREATE TABLE duty_reports (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  assignment_id INTEGER NOT NULL REFERENCES duty_assignments(id),
  teacher_id INTEGER NOT NULL REFERENCES teachers(id),
  duty_date TEXT NOT NULL,
  content TEXT,                   -- 文字说明（选填）
  status TEXT NOT NULL DEFAULT 'pending',  -- pending / grade_approved / approved / rejected
  filled_by INTEGER REFERENCES users(id),
  grade_reviewed_by INTEGER REFERENCES users(id),
  grade_reviewed_at TEXT,
  reviewed_by INTEGER REFERENCES users(id),
  reviewed_at TEXT,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- 日报截图（复用 application_attachments 结构）
CREATE TABLE duty_report_attachments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  report_id INTEGER NOT NULL REFERENCES duty_reports(id),
  filename TEXT NOT NULL,
  stored_path TEXT NOT NULL,
  size INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

固定排班在**录入时展开**成多条 `duty_assignments`（按「星期 + 起始日期」区间生成每一天），日报逻辑对临时/固定完全统一。

## 三、接口设计

新增 `server/src/routes/duty.js`（挂 `/api/duty`），复用现有 `authRequired`、`roleRequired`、`CLERK_ROLES`、`DIRECTOR_ROLES`、`attachmentStorage` 附件存储。

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/duty/assignments?from&to&teacher_id` | 登录 | 值日排班列表（管理员看全部，教师只看自己） |
| POST | `/api/duty/assignments` | CLERK+组长 | 安排值日：临时(单个 date) 或固定(day_of_week+from+to 展开) |
| DELETE | `/api/duty/assignments/:id` | CLERK+组长 | 删除排班（未交日报的） |
| GET | `/api/duty/my-duties` | 登录 | 值日老师自己待履职/已履职的排班 |
| POST | `/api/duty/reports` | 登录(本人) | 提交日报（multipart，含截图） |
| GET | `/api/duty/reports?status` | 登录 | 日报列表（按角色作用域） |
| PATCH | `/api/duty/reports/:id/review` | 年级组长/教务主任/admin | 两级审批 |
| GET | `/api/duty/attachments/:id` | 登录 | 预览截图 |

计酬：`PATCH /reports/:id/review` 终审通过时，复用现有 `applyQnaPayroll` 的值日分支逻辑，生成 `lesson_instances`（`period_type='值日'`、`manual_pay=档位金额`、`source='duty'`），由 `computePay` 手工金额分支计酬。

## 四、前端改动

### 桌面端（Applications.jsx）

- 新增「值日安排」区块（管理员/组长可见）：录入临时/固定排班、查看排班列表、审核日报。
- 复用现有 `form-grid` / `card` / `badge` 样式，与整体墨绿×琥珀金风格一致。

### 手机端（MobileApply.jsx）

- **移除**首页「申报值日」卡片及值日表单（教师不再自主报值日）。
- 新增「我的值日」入口：查看自己未来/历史值日排班，对未提交日报的排班「交日报」（选截图 + 文字）。
- 审核角色（年级组长/教务主任）在手机端可审日报。

## 五、迁移与兼容

- 保留 `duty_pay_tiers` 档位配置（现有 `GET/PUT /applications/duty-pays` 继续用）。
- 保留 `qna_lessons` 里历史「值日」数据与 `lesson_instances` 里已有的值日计酬记录不动。
- 撤下手机端值日入口，不影响历史数据展示。

## 六、实施顺序

1. db.js 建三张表。
2. 新建 duty.js 路由（排班 CRUD + 日报 + 审批 + 计酬）。
3. 桌面端 Applications.jsx 值日安排 + 日报审核。
4. 手机端 MobileApply.jsx 撤值日入口 + 我的值日 + 交日报 + 审日报。
5. 构建验证。
