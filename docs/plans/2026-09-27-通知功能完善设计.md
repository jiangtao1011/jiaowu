# 通知功能完善：美化 + 互动设计

日期：2026-09-27

## 一、目标

现有通知只有「新建（标题/类型/内容）+ 发布/下线 + 复制分享链接 + 纯文本分享页」。本次完善：

1. **美化**：管理后台列表 + 新建表单 + 分享落地页（工作群门面）。
2. **互动**：已读回执、附件下载、回复/评论、点赞表态，四项全做。

## 二、已确认决策

1. 互动身份：**登录或用姓名**——有 token 用账号身份，无 token 则访客填姓名（可选手机号）。
2. 回复可见性：**管理员审核后公开**（pending → approved/rejected）。

## 三、数据模型（新增 4 张表）

| 表 | 字段 | 说明 |
|---|---|---|
| `notice_reads` | notice_id, user_id, visitor_name, visitor_phone, read_at | 已读回执；登录按 user_id、访客按 visitor_name 去重 |
| `notice_attachments` | notice_id, filename, stored_path, size, created_at | 附件；存 UPLOAD_DIR |
| `notice_replies` | notice_id, user_id, author_name, content, status, created_at, reviewed_by, reviewed_at | 回复；status=pending/approved/rejected |
| `notice_likes` | notice_id, user_id, visitor_name, created_at | 点赞；同已读去重 |

## 四、身份机制

新增 `authOptional` 中间件（auth.js）：解析 Bearer token，有则 `req.user`，无则 `req.user=null`，不拦截。互动接口统一用它，身份字段：登录用 `user_id`，访客用 `visitor_name`。

## 五、API

公开（免登录，可选 token）：
- `GET /notices/share/:token` → 通知 + 附件 + 已读数 + 赞数 + 公开回复 + 当前身份是否已读/已赞
- `POST /notices/share/:token/read` → 记已读（body: name?）
- `POST /notices/share/:token/like` → 点赞/取消 toggle（body: name?）
- `POST /notices/share/:token/replies` → 提交回复（body: name, content）
- `GET /notices/attachments/:id/download` → 下载附件（免登录）

管理（需登录）：
- `GET /notices` → 列表 + read_count/like_count/reply_count
- `GET /notices/:id/detail` → 已读名单 + 回复列表（全状态）
- `POST /notices` → 新建（multipart，支持附件 files[]）
- `PATCH /notices/:id/publish` → 发布/下线
- `PATCH /notices/replies/:id/review` → 审核回复
- `DELETE /notices/:id` → 删除

## 六、前端

- `NoticeView.jsx` 重写：美化卡片 + 附件下载列表 + 已读确认（登录自动记/访客填姓名）+ 点赞按钮 + 回复表单（提交后提示待审核）+ 公开回复列表。
- `Notices.jsx` 重写：美化列表（类型色、状态、已读/赞/回复计数）+ 新建表单（类型、附件上传）+ 详情弹窗（已读名单 + 回复审核）。
- `index.css` 增加通知相关样式（附件、回复、点赞、类型色）。

## 七、关键点

- 已读回执：登录用户打开自动记；访客填姓名后主动「我已阅读」记，避免打扰。
- 点赞 toggle：同一身份再点取消。
- 回复审核：后台审核通过后才在分享页公开。
- 附件：复用 multer + UPLOAD_DIR，大小限制沿用 20MB。
