# 课酬财务报表方案（汇总 + 明细导出 + WorkBuddy 联动）

日期：2026-10-06（定稿）

## 目标

让财务人员能「快速、准确地审核」课酬并完成打款。三个关键词：**钱数对得上、来源看得清、审完不变数**。

## 一、现状与定性（先厘清「课酬」到底指什么）

经确认，课酬口径为：

| 课型 | 折算课时 | 课酬（元） | 定性 |
|------|---------|-----------|------|
| 常规正课 | 节数 ×（学科系数+班额系数） | **不计钱** | 折算课时仅供后续「教学业绩考核」用 |
| 早自习 | 节数 × 早自习系数 | **不计钱** | 同上 |
| 按次计酬（晚自习/答疑/晚练/自定义） | 0 | 单价 × 节数 | ✅ 计钱，已有 |
| 非规时段（夏/冬令营/全员/节假补课） | 节数 | 节数 × `pay_standard[时段]` | ✅ 计钱，已有 |

**结论**：课酬（钱）= 按次计酬 + 非规时段两类，金额在 `server/src/context.js` 的 `computePay` 里**已经算对**。正课/早自习只出折算课时，不发钱。因此本方案**不需要新增任何单价配置**，重点放在：报表呈现、自动对账、归档固化、WorkBuddy 联动。

## 二、现有报表的三处缺口（问题定位）

现有导出在 `server/src/routes/stats.js`：`/export`（明细）、`/financial-report`（汇总）。三处硬伤：

1. **非规时段课酬不可见**：夏/冬令营正课的 `period_type` 仍是「正课」，`term` 才是「夏令营/冬令营」。汇总表只按 `period_type` 分列节数，夏令营的钱被埋进「正课节数」和 `pay_total` 总额里，财务看不到「夏令营课酬 X 元、节假补课 Y 元」。

2. **按次计酬只列节数、不列金额**：汇总表按类型列出「晚自习 3 节」，但没列「晚自习 450 元」，财务要自己乘单价。

3. **代课/停课链路断裂**：`queryRows` 直接 `cancelled=0` 过滤，代课产生的「原教师停课 + 新教师上课」只剩新教师半条，明细表里财务看不到这笔钱是代课产生的、原来是谁的。

## 三、主线一：导出功能分层（四层报表 + 归档固化）

财务审核全链路四层，从「看总数」下钻到「这笔钱从哪来」，任何一层对不上都能定位：

### L1 财务审核汇总表（增强现有 `/financial-report`）

按教师一行，**金额按「钱的来源」分列**，不再只分节数：

```
序号 | 教师 | 正课折算课时 | 早自习折算课时
     | 晚自习(元) | 答疑(元) | 晚练(元) | …(按次计酬各类型金额)
     | 夏令营(元) | 冬令营(元) | 全员夏令营(元) | 全员冬令营(元) | 节假补课(元)
     | 课酬合计(元) | 备注
```

- 折算课时列（正课/早自习）不计钱，标注「仅供考核」。
- 金额列 = 节数 × 单价，直接给财务审的钱数。
- 末尾：合计行 + 签字栏（制表/审核/财务复核/校长审批）。
- **新增「口径说明」sheet**：区间、各类型单价、非规时段各档标准、系数快照、生成人/生成时间。审核的前提是「按什么价算的」要白纸黑字。

### L2 课酬明细表（增强现有 `/export`）

每节一行，补三个可追溯列：

- **来源**：课表 / 代课 / 加课 / 申报（`lesson_instances.source`）
- **原教师**：代课记录显示「被谁代」（`parent_id` 回链）
- **状态**：停课记录不再静默丢弃，保留并标「已停课」

> 明细层保留全貌（含已停课、代课双方），财务才能把每笔钱对应到原始课务动作。

### L3 勾稽校验报告（新增 `/financial-check`）

「快速、准确审核」的关键——**自动对账，不让财务手工算**：

1. **三方勾稽**：明细小计 = 汇总小计 = 应发总额，任一不等即标异常。
2. **异常清单**：
   - 非规时段缺课酬标准（`pay_standard` 无对应 term）
   - `period_type` 不在字典且非正课/早自习（无价类型）
   - 单人课酬超阈值（如 > 该教师历史均值 2 倍）
   - 代课计数：被代课教师 + 代课教师各一节，是否双计/漏计
3. **交叉汇总**：按学科、按年级、按课酬类型的金额小计，与总合计对平。

### L4 归档固化（新增 `payroll_snapshots`）

财务审核通过后，把该区间数据固化成快照（存区间、教师、金额、口径 JSON），**之后重新生成上课记录、改课表、改单价，都不影响已归档月份的报表**。这是财务最怕的「审完又变数」的根治手段。现有 `as_of` 快照只覆盖课表，不覆盖已展开的 `lesson_instances`。

## 四、主线二：WorkBuddy 联动（MCP + 技能）

现有 MCP 已有 `edu_summary` / `edu_export_payroll`（`mcp/src/index.js`），技能 `payroll-report`。在其上扩展：

### MCP 新增工具

| 工具 | 用途 |
|------|------|
| `edu_financial_check` | 一键对账：拉 summary + 明细 + 校验，返回勾稽结果与异常清单（文本结论） |
| `edu_export_financial_pack` | 导出「财务审核包」：单文件多 sheet（汇总 + 明细 + 对账报告 + 口径说明） |
| `edu_archive_payroll` | 固化指定区间的报表快照 |

### 技能升级

`payroll-report`（`.claude/skills/payroll-report/SKILL.md`）从「导出两张表」升级为「**财务对账工作流**」：

```
标校历 → 生成上课记录 → 对账校验(edu_financial_check) → 修正异常 →
导出审核包(edu_export_financial_pack) → 固化(edu_archive_payroll) → 给出核对结论
```

关键：技能提示词要求 agent **在导出前先跑对账、报告异常、等用户确认再出包**，而不是直接吐一张表——这才是「准确」。

## 五、落地清单（改动点汇总）

| 层 | 文件 | 改动 |
|----|------|------|
| 报表 | `server/src/routes/stats.js` | 增强 `/export`（来源/原教师/停课态）、`/financial-report`（金额分列+口径说明）；新增 `/financial-check`、归档接口 |
| 前端 | `client/src/pages/Stats.jsx` | 「导出财务审核包」按钮 + 对账结果展示 |
| MCP | `mcp/src/index.js` | 新增 `edu_financial_check` / `edu_export_financial_pack` / `edu_archive_payroll` |
| 技能 | `.claude/skills/payroll-report/SKILL.md` | 升级为对账工作流 |
| 归档 | `server/src/db.js` | 新增 `payroll_snapshots` 表 |

> 不新增单价配置、不加教师银行账号字段（已确认：正课/早自习不计钱、暂不需发放清单）。

## 六、实施顺序建议

1. **先做 L1/L2 报表增强**（金额分列 + 明细可追溯）——财务立即可用，收益最大。
2. **再做 L3 勾稽校验**——把「准确」从人工变成自动。
3. **最后做 L4 归档固化 + MCP/技能联动**——把流程闭环，接入 WorkBuddy。
